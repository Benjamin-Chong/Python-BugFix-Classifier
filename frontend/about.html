Disclaimer

This is a machine-learning model and it can make mistakes. When entering your buggy and fixed code, the label may not be representative of your expected fix. Please refer to the section below.

Selected RunBugRun Categories

  1. Assignment: the fix changes an assignment, such as the value being assigned, the assignment target, or the assignment operator.
  2. Call: the fix adds, removes, or modifies a function/method call, including its arguments.
  3. Control Flow: the fix changes how execution proceeds, such as an if condition, loop, branch, break, continue, or return.
  4. Expression: the fix changes an expression or operation, such as arithmetic, comparison, binary, or unary operators.
  5. Identifier: the fix changes an identifier such as a variable, function, method, or attribute name.
RunBugRun uses a hierarchical, multi-label taxonomy containing 136 fine-grained leaf labels and 16 broader stem labels. A single bug may receive multiple labels. This project simplifies that taxonomy into five mutually exclusive categories for classification.

Progression:

  1. The project began as a single PyTorch classifier but evolved into a controlled comparison of three model architectures.
  2. V1 established a classical baseline using TF-IDF representations with scikit-learn classifiers.
  3. V2 introduced learned token embeddings with masked mean pooling, creating an intermediate model between the fixed TF-IDF representation and the sequence-aware Transformer.
  4. V3 added positional encoding and self-attention. I then compared all three models using accuracy, macro F1, weighted F1, and class-level confusion patterns.

Limitations

  • This application predicts the type of code change, not whether the submitted fix is correct.
  • It only supports Python code.
  • RunBugRun's original multi-label taxonomy was simplified into five single-label categories.
  • The models were trained on short programming solutions, so predictions may not be able to generalize to large production codebases.
  • A diff may contain several kinds of changes, but each model returns only one category.
  • V3 accepts at most 1,024 tokens.
  • The models may disagree or perform poorly on small, artificial, or unfamiliar examples.
